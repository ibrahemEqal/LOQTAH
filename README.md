# لقطة · LOQTAH

منصة عربية لإدارة إنتاج المحتوى الإعلاني للعلامات المحلية، من طلب الحملة إلى الموافقة على التسليم. تصميم RTL متجاوب، خط عربي محلي، وهوية مستقلة بلون المرجان.

## ما يعمل حاليًا

- تصفّح ملفات المواهب التوضيحية والبحث والتصفية حسب المجال والمدينة.
- ملفات تفصيلية، مراجع بصرية، وحفظ المفضلة في الحساب أو محليًا للزائر.
- باقات استرشادية وطلب حملة من 3 خطوات، مع مسودة مؤقتة في جلسة المتصفح.
- تسجيل دخول عبر ChatGPT تديره منصة الاستضافة؛ لا تُخزّن كلمات مرور.
- حفظ فعلي للحملات والمفضلة والمراسلات والتسليمات وطلبات الانضمام في D1.
- لوحة حملات بإحصاءات من سجلات المستخدم، تفاصيل الحملة، متابعة المراحل وسحب الطلب قبل التخطيط.
- مراسلات لكل حملة، موافقة على المحتوى وطلب تعديلات مع ملاحظات.
- طلب انضمام لصنّاع المحتوى وتعديل الملف الشخصي.
- لوحة إدارة محمية لمراجعة طلبات الانضمام، تحديث المراحل بالتسلسل، مراسلة العميل، وإضافة روابط تسليم HTTPS.
- عزل البيانات على الخادم حسب هوية المستخدم؛ الموافقة على جميع التسليمات شرط لإكمال الحملة.

## حدود النسخة الحالية

**نسخة خاصة للتجربة وليست إطلاقًا تجاريًا مكتملًا.** الأسماء وملفات المواهب أمثلة افتراضية، والصور صور توضيحية من Unsplash. لا تعني شراكة أو توافرًا أو أن الأعمال المرجعية من إنتاج الأشخاص المعروضين. أسعار الباقات افتراضات قابلة للتعديل، وليست تسعيرًا تجاريًا معتمدًا.

لا يوجد دفع إلكتروني، نشر آلي للشبكات الاجتماعية، ضمان نتائج، إشعارات بريدية، تقارير تحليلات متصلة، أو رفع ملفات خاصة. التسليمات روابط يضيفها المشرف؛ استخدم روابط بمشاركة مضبوطة ولا تنشر مواد سرية. قبول طلب صانع محتوى لا ينشئ ملفًا عامًا تلقائيًا؛ يُراجع وينشر بشكل منفصل. إدارة الكتالوج والباقات حاليًا من `app/lib/catalog.ts`.

## التقنية

- React 19 + TypeScript.
- App Router عبر Vinext / Vite؛ تشغيل الخادم على Cloudflare Workers.
- Cloudflare D1 + Drizzle ORM مع ترحيلات SQL ملتزمة بالمستودع.
- Zod للتحقق على الخادم، وLucide للأيقونات.
- CSS مخصص وIBM Plex Sans Arabic محليًا؛ لا يعتمد عرض الخط والصور على تحميل من طرف ثالث.

هذا مشروع Workers، **وليس مشروع Next.js جاهزًا للنشر على Vercel كما هو**. استضافة Sites تدير موارد D1 وتسجيل الدخول وترحيلات قاعدة البيانات. يحتفظ `worker/index.ts` و`vite.config.ts` بتكامل الاستضافة.

## تشغيل محلي على macOS / Windows / Linux

يلزم Node.js 22.13 أو أحدث (يفضّل 24)، وpnpm بالإصدار المسجّل في `package.json`.

```bash
git clone https://github.com/ibrahemEqal/LOQTAH.git
cd LOQTAH
npm install -g pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm dev
```

الإعداد المحلي يختار وضع portable تلقائيًا عند عدم وجود إعداد خاص بالبيئة. يحاكي تسجيل الدخول **على loopback محليًا فقط**. افتح مسار `/signin-with-chatgpt?return_to=/` للحساب المحلي؛ هذه المحاكاة غير موجودة في بناء الإنتاج.

قبل اختبار البيانات محليًا، ابنِ المشروع ثم طبّق الترحيل على D1 المحلية:

```bash
pnpm build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_odd_blockbuster.sql
pnpm dev
```

لا تعِد تطبيق الترحيل نفسه على قاعدة سبق ترحيلها. قواعد التطوير والإنتاج منفصلة. لتغييرات schema لاحقة:

```bash
pnpm db:generate
```

راجِع SQL الناتج، طبّق الترحيل الجديد محليًا، والتزم بملفات `drizzle/` كلها. لا تعدّل ترحيلًا مطبقًا.

## الاختبارات

```bash

```

الاختبارات تشغّل معالجات API الفعلية مع هويات اختبار وقاعدة SQLite في الذاكرة. تغطي عزل حسابين، رفض الكتابة دون دخول، التحقق من المدخلات، المفضلة، طلبات الانضمام، مراحل الإدارة، المراسلات، الموافقات ومنع إكمال حملة دون موافقة.

## تفعيل حساب الإدارة

الافتراضي: **لا أحد مشرف**. لا يُمنح أول مسجّل صلاحية تلقائية. أضف متغير الخادم `LOQTAH_ADMIN_USER_IDS` إلى إعدادات بيئة الاستضافة بقائمة معرّفات حسابات Sites المصرح لها، مفصولة بفواصل. استخدم معرف الحساب الخاص بهذا الموقع، لا البريد الإلكتروني ولا اسم GitHub. لا تضع قيمًا حساسة في المصدر أو واجهة المتصفح.

بعد التفعيل يظهر زر لوحة الإدارة في لوحة حملات الحساب المعني. الإدارة تتحقق من الصلاحية على الخادم في كل طلب. المتغير لا يُعدَّل من واجهة العميل. للتطوير المحلي فقط، يمكن إضافة `LOQTAH_ADMIN_USER_IDS=local_seedy` إلى ملف `.dev.vars` غير الملتزم.

## النشر والأمان

- `.openai/hosting.json` يعرّف الموقع وربط D1 باسم `DB`.
- النشر الأول خاص بالمالك؛ تغيير الجمهور خطوة منفصلة.
- لا ترسل حقول `userId` أو `isAdmin` من العميل لإثبات الصلاحية؛ الهوية تُقرأ على الخادم.
- POST يتطلب JSON وOrigin مطابقًا، مع حدود لحجم الطلب والتحقق من المدخلات.
- لا تعرض Worker مباشرة للعامة خلف وكيل يسمح بتزوير ترويسات `oai-authenticated-user-*`. إثبات الهوية في الإنتاج تعتمد عليه بوابة Sites الموثوقة. للنشر المستقل يجب استبدال مزود الهوية وربط D1 وموارد Cloudflare بطريقة مناسبة.
- روابط التسليم ومعارض الأعمال تقبل HTTPS فقط، وتفتح مع `noopener noreferrer`.
- لا يُحمّل الخادم روابط يرسلها المستخدم، ولا ينفّذ HTML مضمّنًا.

قبل فتح المنصة للعامة: أدخل مواهب حقيقية بموافقاتهم، اعتمد التسعير والعقود وحقوق الاستخدام وسياسة الاحتفاظ، فعّل حساب الإدارة وقناة الدعم، ثم اختبر دورة حملة فعلية مع حسابين.
